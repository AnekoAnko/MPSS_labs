# Шпаргалка до захисту ЛР №7 (мініпроєкт)

## Ланцюг системи одним реченням
Акселерометр (SensorReader → MonitorViewModel → **SensorHub**) → **AiViewModel** (TFLite, Dispatchers.Default) → «Аномалія» в **SystemStateRepository** → **ControlViewModel** (сирена + прожектор, `alarmActive = true`) → паралельно: **AnalyticsViewModel** пише подію в Room → **SensorRepository** шле в Firebase; ControlViewModel шле `status/` з `critical`; **BleViewModel** шле `ALARM:ON` на AR-Hub-46; **Dashboard** показує все.

## Ключові терміни
- **Системна інтеграція** — об'єднання модулів у цілісну систему з наскрізними сценаріями.
- **DI (Dependency Injection)** — об'єкт отримує залежності ззовні (через конструктор), а не створює сам.
- **Manual DI** — без бібліотек: `AppContainer` створює об'єкти, `AppViewModelFactory` передає їх у ViewModel.
- **Service Locator** (було: `AppGraph`) — клас сам бере залежності з глобального об'єкта; залежності приховані.
- **Offline-first** — спершу локальна БД, потім хмара; черга досилається після відновлення мережі.
- **Медіанний фільтр** — бере медіану останніх N вимірів, повністю ігнорує одиночні викиди.
- **Витримка (debounce)** — умова має триматися заданий час, щоб спрацювати.
- **Гістерезис** — поріг увімкнення і вимкнення різні, щоб не «блимати» біля порога.
- **Memory leak** — об'єкт, який уже не потрібен (стара Activity), не звільняється, бо на нього є посилання.

## Питання і відповіді
1. **Що станеться, якщо закінчиться місце для БД?** Room кидає `SQLiteFullException`. Репозиторій видаляє 1000 найстаріших записів, які вже є в хмарі (`synced = 1`), і пробує знову. Якщо таких немає — вимір іде лише в хмару, Dashboard показує попередження. Додаток не падає, несинхронізовані дані не видаляються.
2. **Що буде без інтернету?** Записи лишаються в Room з `synced = 0`, лічильник «у черзі» росте. Коли мережа повертається, `CloudViewModel` викликає `syncPending()`; черга переживає навіть перезапуск додатка.
3. **Навіщо DI, якщо все працювало з AppGraph?** Залежності тепер видно в конструкторі, їх легко підмінити фейками (так перевірено весь сценарій на JVM), і ViewModel не залежить від глобального стану.
4. **Чому не Hilt?** Методичка дозволяє Manual DI; без анотацій і генерації коду весь граф видно в одному файлі. Перейти на Hilt легко — конструктори вже готові.
5. **Як захищено від хибних спрацювань?** LPF (ЛР1), медіанний фільтр (налаштовується 1/3/5/9), витримка правила, гістерезис, підтвердження прогнозу 2 рази поспіль (ЛР6). Демонстрація: `spike` з фільтром 1 і витримкою 0 → спрацьовує; з фільтром 5 → ні.
6. **Як Dashboard вмикає ліхтарик, якщо ним керує ControlViewModel?** Через шину: `ActuatorRequest` → `SystemStateRepository.requests` → `ControlViewModel.onRequest()`. ViewModel не викликають одна одну.
7. **Що буде, якщо хаб не підключено під час тривоги?** У журналі BLE — попередження, а `ALARM:ON` надсилається одразу після підключення. Mock повторює запис до 3 разів з backoff.
8. **Як перевіряли витоки пам'яті?** Profiler → Memory: 10 хв `demo` + повороти + згортання → графік без росту; Force GC → heap dump → одна `MainActivity`. Слухачі знімаються в onPause/onStop, контейнер тримає лише Application, корутини — у viewModelScope.
9. **Чому шина requests без replay?** Щоб після повороту екрана нова підписка не виконала стару команду ще раз.
10. **Як перейти на реальне залізо?** Нова реалізація `IBleConnector` через BluetoothGatt + ESP32; Foreground Service для сенсора; WorkManager для синхронізації; Firebase Auth.
